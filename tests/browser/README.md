# Browser regression tests

Fresh headless Chromium/Firefox instances exercise the real Rust server, isolated SQLite/storage and built Dioxus WASM. No signed-in browser profile is used. `server.sh` owns and removes its own mktemp directory, never the development library.

```bash
cargo build --locked -p vela-server
scripts/build-web.sh
npm ci --prefix tests/browser
(cd tests/browser && npx playwright install chromium firefox)
(cd tests/browser && npx playwright test --browser=chromium)
(cd tests/browser && npx playwright test --browser=firefox)
```

Use `VELA_LIVE_IMPORT_TEST=1` to include the external direct-download import test; ordinary tests are deterministic and offline after dependency installation. The live test uses **Example.ogg by JesseW**, licensed [CC BY-SA3.0](https://creativecommons.org/licenses/by-sa/3.0/) and documented at [Wikimedia Commons](https://commons.wikimedia.org/wiki/File:Example.ogg). It downloads the unchanged original into temporary private test storage; no copy is included in this repository. The local FLAC fixture and its cover were generated by this project.

Screenshots/traces appear under test-results and are untracked. Audio validation establishes that the selected browser decoded the file, reported positive duration, advanced playback time and had no HTMLMediaElement error; it does not verify physical speaker output, bit-perfect reproduction, gapless playback, OS background audio or mobile hardware behavior.

The suite also verifies private album/artist browsing/playback, stale collection responses, revisioned catalog edits with two real authenticated browser sessions, original playback after edits, draft-preserving conflicts, explicit reload, mobile dialog layout and cancellation before an account change. The configured-folder scenario uses real nested FLAC/MP3 files, scans through Settings, verifies dedup preserves edited tags, plays newly scanned audio, rescans, removes the source without deleting music, and checks a mobile layout. A full0.8 run has33 scenarios; the live network import is opt-in (32 deterministic scenarios otherwise). Filter scenarios cover combined private filters/favorites/sorting, invalid drafts/reset/mobile layout, out-of-order filters, stale private suggestions after an account change, and real50+2 pagination while draft fields differ. That last scenario uploads52 distinct generated PCM WAV files through the production endpoint in isolated storage; it does not mock catalog responses. Scenarios reuse only earlier authenticated sessions belonging to this suite, held in memory, to keep the production login limiter unchanged.

Jobs scenarios inspect the real licensed import when enabled, run52 actual passes over the private FLAC/MP3 folder, use Scan again through the UI and verify preserved50+2 history pages, stable older-page refresh and real navigation. At320px five primary navigation controls remain visible; More exposes the remaining authorized destinations. Delayed responses use route.fetch() against the real API before holding/releasing them; only the deliberate HTTP503 outage is injected. Tests verify filter races, visible stale-data recovery, account-change isolation and absence of legacy import polling on Jobs. The unit/TCP suites separately verify deterministic queued import cancel/retry and scan cancellation/action authorization without relaxing public egress. No job history response or database row is fabricated by browser tests.

PLNAV01 (scenario20 in0.6.1) holds real playlist details across navigation away/back, a real deletion's follow-up GET across another selection, and an actual share-token POST response across another playlist. It asserts that abandoned responses cannot reopen a detail or display another playlist's link, while the server mutation remains committed. The same PLNAV01 scenario commits an out-of-band authenticated API edit while an earlier same-view refresh is held. A stale UI reorder receives the genuine409 and fetches the newer revision; releasing the older snapshot must not lower the displayed revision or remove newer rows. This is a real same-account concurrency regression, not a device-handoff claim.

Playback0.7 adds RES01–04, NET01–02 and AUTH01 to the same real-server suite. Locally generated30s PCM tests paused context/position/preferences restore, duplicate occurrences, bounded invalid storage, real aborted/held media and HEAD requests, retry exhaustion/cancellation, playlist context and genuine revocation of a dedicated fixture session. No production cookies or catalog responses are fabricated. Recovery screenshots at320px cover both themes and a44px retry target. Reuse only this isolated suite’s fixture sessions; retain the production login limiter. Native output, offline files, other browsers and OS services require separate evidence.

Now Playing0.8 adds NP01–03 and extends NET02/AUTH01/account-switch coverage. Controls/metadata/queue/favorites operate on the existing root audio. Tests inspect a paused item without fetching audio, verify a real30s duration before metadata loading, preserve dialog/audio identities across actual Media Session Next/Pause/Play, reject held favorite feedback for an old occurrence/view/account, and verify responsive screenshots/focus/native close. The test adapter wraps the actual Media Session registration and calls its registered handlers; this is not physical headset validation.

Run each engine in a separate invocation as above, so server.sh creates fresh isolated storage/accounts. This serial suite deliberately shares its fixture state within one run; do not use --browser=all against its single webServer. Preserve screenshots/traces before the next invocation overwrites test-results. CI runs the engines sequentially with separate temporary databases and retains Chromium artifacts before Firefox; configured CI is not evidence of a remote run.

The Firefox trace showed buffered-resource reuse after reload with no new GET. Network-fault setup therefore releases only the paused test element's buffer through native pause/remove-src/load, retains the real saved bookmark/backend, and verifies the saved position after reload. This cold-source setup makes the actual transport outage reachable. NET01/NET02 keep every genuine GET failing until Vela's HEAD starts, retaining real backend responses and seek/cancellation assertions. NET01 also requires a source-generation change after the probe begins, distinguishing the application reload from a browser-only retry. Its15s wait allows the8s watchdog. No production retry policy or authorization check is weakened.
