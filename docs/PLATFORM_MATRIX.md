Installed Rust targets are x86_64-unknown-linux-gnu, wasm32-unknown-unknown and aarch64-linux-android. No mobile/native client has been silently substituted with a browser WebView. The0.12.6 Linux desktop client is a real Dioxus/WebKitGTK window with a native Rodio/CPAL output thread and MPRIS observer; a WebView was not used for audio, and the web player remains a separate target. The Windows, macOS, Android and iOS clients are the same Rust application behind their platform shell; each compiles for its target (Android against the Android NDK r26d with the platform audio stack, the others on their own CI runners). No mobile client has been run on real hardware, packaged as an application project, signed or submitted to a store, so those steps stay NOT_RUN rather than inferred from a successful compile. Native next work is fixing the audited offline/keyring lifecycle defects and a real cold-start-without-server path (AUD-01–AUD-08), then Android Media3 foreground service and Apple AVFoundation on their real toolchains; Linux packaging, session persistence, offline copies and folders are implemented to the0.12.6 scope above. Audio must outlive UI route/lifecycle changes; Linux window evidence does not certify mobile background audio. Android's [Media3 ExoPlayer documentation](https://developer.android.com/media/media3/exoplayer) was checked during this session; no Android version or hardware compatibility is claimed without a build.
