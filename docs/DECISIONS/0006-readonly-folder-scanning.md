# ADR0006: configured read-only sources with managed snapshots

Status: accepted,2026-10-14.

Existing NAS/music folders need browser-managed scanning without granting an ordinary account arbitrary host filesystem access. Configured storage mounts are installation authority; the application exposes opaque root IDs/display names to the administrator and never accepts media paths through source APIs. Default root is data/sources; explicit VELA_SCAN_ROOTS JSON declares operator-approved absolute roots or [] disables scanning. Traversal/overlapping managed/system paths and aliases are rejected.

A cohesive scanner crate owns filesystem capabilities, immutable snapshots and durable scan jobs. cap-std/cap-fs-ext4.0.3 were verified against upstream registry/source. Every root/path component is opened without following symlinks, relative to held directory descriptors; nested scans use bounded depth-first iterators. Regular-file checks, Unix hardlink rejection, nonblocking opens, file/entry/depth/map/queue ceilings and chunked staging limit resource use. This first implementation intentionally supports Linux filesystem semantics; other server platforms require separate validation. Deadlines/cancellation are checked between OS calls; a broken/network filesystem can block a kernel read and is not given a hard termination guarantee.

Source audio is read-only. A supported file is copied into owned staging, checked for normal descriptor changes, fsynced and passed to existing MediaService.ingest. Managed immutable bytes keep HTTP streaming/authorization/backups independent of later source edits/unavailability. This uses extra storage; direct referencing of external source files is a future storage mode. Rescans cache size/mtime/device/inode signatures under hashed relative paths, a best-effort change detector rather than content revalidation. Changed files append/deduplicate snapshots; missing files never delete catalog tracks. Existing exact owned tracks retain catalog edits.

SQLite stores sources, bounded active jobs, counters/cancellation and per-source file fingerprints. Ownership constraints prevent foreign map references. One serial scanner and the existing import worker share bounded media processing. Startup requeues interrupted scans and clears recognized unpublished scanner staging; global data lock prevents competing cleanup. Cancellation finishes any already-started atomic ingestion, then stops; shutdown requeues interrupted work. Infrastructure failure stops the process. HTTP listener is acquired before launching workers.

The administrator UI creates/removes sources, enqueues/cancels scans and polls active progress. Source removal deletes tracking/history only, retaining owned media. No arbitrary filesystem browser, folder write/delete, public registration or sharing grant is introduced. Trust boundaries and external mount setup are documented in SECURITY/OPERATIONS.
