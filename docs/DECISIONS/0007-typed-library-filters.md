# ADR0007: typed private library filters and keyset ordering

Status: accepted,2026-10-15. Implementation verification is tracked in PROGRESS.

A large library needs combined genre/year/technical-property filters without arbitrary SQL or downloading the whole catalog. Extend the native track-list contract with a typed filter value and a closed sort enum; the existing default UUID ordering remains compatible. Search, favorites and all filters are conjunctive with ownership. Values are bound SQL parameters, and numeric/text limits are validated in the application service even when called outside HTTP. Malformed transport values receive fixed JSON400 responses.

Genre matches a complete trimmed tag with SQLite ASCII NOCASE, consistent with provisional catalog grouping. Do not guess multiple genres from punctuation or equate Unicode strings beyond the database collation. Format labels describe the existing reader's codec/container information; MP4/WAV/WavPack and high sample rates do not prove losslessness. Numeric thresholds exclude unknown properties. The interface names units explicitly: stored bitrate is kbps, sample rate is Hz, bit depth is bits.

Title and newest ordering use a UUID tie-breaker and keyset comparisons. A cursor contains the last row's opaque UUID; the service resolves its key within the authenticated owner's SQLite read snapshot and rejects foreign/missing rows uniformly. No OFFSET or unbounded client result is introduced. Concurrent edits/additions can move boundaries between page requests; this is documented live pagination, not a cross-request snapshot. The frontend returns to the first page after applying changed conditions.

Separate draft fields from successful applied conditions. Paging and catalog refresh use committed search/filters; invalid drafts retain the current result. Account changes clear drafts, applied conditions and suggestions. Generation/session guards discard delayed requests. Facets are independently private and bounded:100 genre values,32 formats, one sentinel and explicit truncation flags; a literal genre text input remains available when suggestions truncate.

Migration0005 adds owner-prefixed expression/collation indexes matching the actual predicates and tuple order. SQLite requires expression matching for expression-index selection; see [Indexes on Expressions](https://www.sqlite.org/expridx.html). Tuple seek semantics follow [Row Values](https://www.sqlite.org/rowvalue.html). The existing bounded FTS probe is preserved. Reproducible SQL measurements will record query plans, added index/storage costs and their exact scope; no HTTP or library-size capacity claim follows from a SQL microbenchmark.

The first100k-owner measurement found grouped genre facets performing random table reads despite the expression index. Migration0006 appends raw genre after the unchanged owner/expression/UUID prefix so the existing canonical MIN query is covering. It preserves0005 as an immutable upgrade step. Baseline and optimized measurements are retained separately; year-range selection is not changed through forced planner hints.

Stable SQLx macro embedding watches previously included migration files but needs a build-script directory watch for new entries. Core now declares cargo:rerun-if-changed=../../migrations, following [SQLx0.8.6 documentation](https://docs.rs/sqlx/0.8.6/sqlx/macro.migrate.html). Packages also carry the expected schema version and verify it after startup. This makes adding a migration a rebuild dependency rather than relying on an unrelated Rust edit.
