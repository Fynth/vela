# ADR0011: browser bookmarks and bounded recovery

Date:2026-10-16. Implemented increment; executed evidence is in PROGRESS.

The root App keeps its existing single HTMLMediaElement and occurrence-based PlaybackOrder. A browser_player.rs adapter owns source generations, pending metadata seeks, play requests, cancellation and recovery. session.rs contains framework-free validation and retry policy. No new crate, database migration, service or dependency version is required.

Use one versioned localStorage value per account, containing queue/cursor/current track binding, playback context, position, volume and modes. Validate owner/version/canonical UUIDs,1000 entries,4MiB serialized bytes, finite bounded position/preferences and context labels. Read legacy queue/cursor as a validated bounded fallback. Preserve legacy structural keys for rollback; the new snapshot is authoritative. Metadata is local plaintext browser data, not an encrypted vault or media-access grant. No session secret, import URL or stream credential belongs in it. Browser storage failures must not stop playback. Seek writes are immediate; playback writes are throttled to5s and flushed on pause, visibility-hidden and pagehide. Abrupt process/OS termination can lose the last checkpoint; unload events are not guaranteed.

Restore paused, without assigning a media source until explicit Play. Apply the saved seek once after matching metadata; new selections start at0. Queue index edits preserve the active source. Source generations distinguish repeated occurrences of the same URL. Every delayed play/probe/retry checks exact current session, generation, element and source. Pause, selection, account change and teardown cancel timers and abort probes. A successful reachability check must never replace authentication or reset the queue.

Transient media failure and lack of actual progress use three bounded delays (500/1500/4000ms), a10s abortable authenticated HEAD probe and an8s progress watchdog. Valid response reloads at the last position. Stable media progress resets the retry budget.401 returns to sign-in and releases private playback state;403/404 and decode failures show an actionable state. Autoplay denial requires another gesture. Retry is explicit after exhaustion. Actual transfer progress matters; navigator.onLine is only a hint and is not used as proof of reachability. A user may continue already buffered authorized audio until the browser needs another request; session revocation cannot erase bytes already delivered.

No offline cache, durable shuffle traversal/listening-history journal, cross-device synchronization, native background service, codec/transcoding extension, audible output or sample-perfect gapless claim follows. Seek precision and autoplay policies are browser-dependent. Unknown/unsupported codecs can exhaust recovery rather than being diagnosed perfectly.

Primary browser contracts: [load](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/load), [currentTime](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/currentTime), [play](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play), [visibilitychange](https://developer.mozilla.org/en-US/docs/Web/API/Document/visibilitychange_event), [pagehide](https://developer.mozilla.org/en-US/docs/Web/API/Window/pagehide_event), [onLine](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/onLine).

## Follow-up0.7.1: requested versus active clock

Previous must evaluate the bookmark when no active media clock exists (paused restore, pending metadata/retry). Read actual currentTime only for the matching, metadata-ready, error-free active element; otherwise use the saved position. A sequential restored occurrence beyond3s therefore seeks to0 without selecting another row or starting a fetch. The RES01 browser case explicitly disables restored shuffle before testing this branch, then seeks the still-unloaded source and resumes it. The0.7.0 local review archive is preserved;0.7.1 is the intended active runtime.
