# Vela: план масштабирования и устойчивости

> Статус: проектный документ, не выполненные работы. Все пункты ниже требуют
> отдельной реализации, тестов и evidence в `docs/PROGRESS.md` и `docs/QA_EVIDENCE.md`.

## 0. Юридическая рамка (обязательна)

Слово «пиратский» в этом документе понимается как **устойчивый к блокировкам,
децентрализованный и не зависящий от одного сервера**, а не как нарушение авторских
прав. Жёсткие границы, которые нельзя обходить:

- Только контент, который пользователь загрузил сам, либо контент с лицензией,
  **явно разрешающей распространение** (CC0, CC-BY, CC-BY-SA, прямые лицензии
  правообладателей).
- Никакого обхода DRM, никаких чужих каталогов без прав, никакого «кэширования»
  платного контента.
- Атрибуция и права фиксируются в публикации (`license`, `attribution`,
  `rights_evidence`) — это уже реализовано в `crates/media/src/publications.rs`.
- Приватные библиотеки не становятся публичными без явного действия владельца.

## 1. Целевые показатели (SLO)

| Метрика | Цель |
|---|---|
| p50 первого байта аудио | ≤ 250 мс (локально), ≤ 800 мс (федерация) |
| p99 API чтения | ≤ 300 мс при 10k RPS |
| Доступность сервера | 99.9% (один узел), 99.99% (кластер) |
| Поиск по 100k треков | p95 ≤ 150 мс |
| Одновременных слушателей | 10k на узел, 100k в федерации |
| Восстановление после падения | ≤ 30 с, 0 потерянных сессий |
| Работа при блокировке origin | ≤ 5 с переключение на зеркало |

## 2. Легальные источники музыки

1. **Свои загрузки** — текущий upload/import/scan уже работает.
2. **Creative Commons каталоги** (легально, с атрибуцией):
   - Free Music Archive, Jamendo (CC-разделы), Musopen, Internet Archive
     (коллекции с явной лицензией), ccMixter.
   - Импорт через существующий controlled egress (`crates/imports`), лицензия
     сохраняется в публикации.
3. **Прямые лицензии независимых артистов** — ручной каталог с
   `rights_evidence`.
4. **Пользовательские «полки»** — каждый владелец может опубликовать свой
   каталог как федеративный публичный профиль (уже есть public catalog).
5. **Нелегальные источники исключены** — импортёр принимает только прямые
   HTTP(S)-ссылки на файлы, а публикация требует `rights_confirmed`.

Правило: «много музыки» достигается **федерацией легальных каталогов**, а не
копированием чужих библиотек. Федерация уже умеет: публичный профиль, каталог,
курсорную пагинацию, права на стрим/скачивание, отзыв публикации.

## 3. Архитектура масштабирования

### 3.1 Уровни

| Уровень | Сейчас | Цель |
|---|---|---|
| Метаданные | SQLite WAL, schema12 | PostgreSQL 16 + партиционирование по owner_id |
| Аудио | локальные immutable files | S3-совместимое объектное хранилище + локальный кэш |
| Поиск | SQLite FTS5 | OpenSearch/Meilisearch + шардирование по owner |
| Очереди | SQLite jobs | Redis Streams / NATS JetStream |
| Кэш | нет | Redis (каталоги, каталог федерации, сессии) |
| CDN | нет | внешний CDN для публичного контента, Range-запросы |

### 3.2 Путь миграции SQLite → PostgreSQL

1. Ввести слой репозиториев (`vela-store`), скрывающий SQLx-запросы.
2. Схема PG повторяет 0001–0012 + новые индексы; владельческие FK сохраняются.
3. Двойная запись/чтение за фича-флагом, сверка counts/hash.
4. Переключение по тенантам, затем полное.
5. SQLite остаётся для single-user/desktop режима.

### 3.3 Аудио-доставка

- Объектное хранилище + подписанные URL с TTL (не публичные пути).
- Range-запросы обязательны (уже есть в media).
- Кэш на edge; для федерации — собственный origin-кэш с проверкой ETag.
- Ограничение полосы на пользователя/узел; приоритет интерактивному стриму.

### 3.4 Воркеры

- Импорт, скан, DSP, рекомендации — отдельные пулы.
- Ограничение concurrency на CPU/IO, cooperative cancel (уже есть).
- При перегрузке — backpressure и 429 с Retry-After.

## 4. Устойчивость к блокировкам

### 4.1 Мульти-origin федерация

- Каждый узел публикует несколько origin (домены/зеркала), подписанных
  ключом сервера.
- Клиент перебирает origin по приоритету, проверяет identity и падает на
  следующий при ошибке/таймауте.
- Кэш «последний рабочий origin» на клиенте (не секрет).

### 4.2 Зеркала и реплики

- Реплика read-only: тот же контент, другой origin, отдельный TLS-сертификат.
- Синхронизация каталога через подписанные снапшоты (Merkle root).
- Переключение DNS/Anycast — операционная задача, не код.

### 4.3 Деградация

- Если origin недоступен: показать кэшированные метаданные (уже есть в native),
  пометить «unavailable», не подменять права.
- Офлайн-копии играют без сервера (уже есть), с BLAKE3-проверкой.
- Очередь/позиция сохраняются локально (bookmark уже есть в web).

### 4.4 Легальный P2P для CC-контента

Только для публикаций с лицензией, разрешающей распространение:
- BitTorrent/WebSeed для CC-BY/CC-BY-SA/CC0 файлов.
- Проверка BLAKE3 и лицензии перед раздачей; отзыв публикации → исключение из
  раздачи (tombstone в DHT не гарантируется — честно документировать).
- Приватный контент в P2P **никогда** не попадает.

### 4.5 Анти-абьюз

- Rate limiting по IP/аккаунту/origin.
- Подписанные запросы федерации, replay-защита (nonce+timestamp).
- Ограничение размеров объектов и глубины каталога (уже есть 128KiB/20).
- SSRF-защита: только HTTPS DNS origin, публичный unicast (уже есть).

## 5. Федерация и «много музыки»

1. **Discovery**: WebFinger/`.well-known/vela` (есть), список доверенных узлов.
2. **Каталог**: публичный каталог с курсорами (есть), поиск по `q` (есть).
3. **Права**: отдельно stream/download/attribution; отзыв (есть).
4. **Кэш метаданных**: только публичные данные, browse-only при недоступности
   (есть в native).
5. **Агрегатор**: узел-«хаб» индексирует публичные каталоги (только метаданные),
   отдаёт поиск; клиент идёт к origin за стримом.

## 6. UX уровня Spotify

- Персональные миксы: on-demand из реальных сигналов (есть), без фабрикации.
- Radio: similarity + «why» (есть).
- Поиск: объединённый по origin, прогрессивные результаты, курсоры.
- Плеер: queue, shuffle, repeat, Now Playing, MPRIS (есть), фоновое аудио
  (мобильные — блокер).
- Офлайн: явные копии + очередь + проверка (есть), мобильные — блокер.
- Доступность: клавиатура, скринридер, en/ru локализация, reduced motion.
- Дизайн: единая система, тёмная/светлая темы, 320px.

## 7. Этапы

### Фаза 0 — измерения (1–2 недели)
- 100k метаданных, 10k RPS read, p95/p99.
- Профиль SQLite/FTS, узкие места.
- Критерий: отчёт с числами в `docs/PERFORMANCE.md`.

### Фаза 1 — хранилище и кэш
- Абстракция object storage + подписанные URL.
- Redis для каталога/сессий.
- Критерий: стрим не зависит от локального диска; тесты Range/ETag.

### Фаза 2 — PostgreSQL
- Слой репозиториев, двойная запись, переключение.
- Критерий: counts/hash/FK совпадают, миграция без потерь, rollback.

### Фаза 3 — федерация на нескольких origin
- Подписанные снапшоты, multi-origin клиент, failover.
- Критерий: отключение origin → клиент переключается ≤5 с, права сохраняются.

### Фаза 4 — мультимедиа-каталог
- Хаб-агрегатор публичных каталогов (только метаданные).
- Критерий: поиск по 3+ узлам, частичные результаты, playable origin.

### Фаза 5 — P2P для CC
- BitTorrent/WebSeed, проверка лицензии и BLAKE3.
- Критерий: раздача только разрешённых публикаций; отзыв исключает из выдачи.

### Фаза 6 — мобильные и десктоп
- Android Media3, iOS AVFoundation, Windows/macOS сборки — только на реальных
  тулчейнах; иначе явно BLOCKED.

## 8. Нагрузочные тесты

- `scripts/benchmark_*` (есть для рекомендаций/каталога).
- Новые: read 10k RPS (k6/wrk), 100k FTS, параллельный DSP+scan+import.
- Критерии: p99 ≤ 300 мс, аудио не деградирует, ошибок < 0.1%.
- Каждый запуск: команда, конфиг, версия, числа — в PERFOMANCE.md.

## 9. Безопасность и права

- Публикация только с `rights_confirmed`; лицензия в ответе API.
- Приватное никогда не индексируется хабом.
- Отзыв публикации → 404 на стрим, из каталога, из кэша (tombstone).
- Аудит-события на публикацию/отзыв.
- Никаких секретов в логах/URL/кэше.

## 10. Риски

| Риск | Митигация |
|---|---|
| Нелегальный контент у пользователя | права подтверждаются, жалобы/удаление |
| Блокировка origin | multi-origin, зеркала |
| Потеря данных | backup/restore, immutable storage |
| Перегрузка | лимиты, backpressure |
| Юридические претензии | только CC/свои/прямые лицензии |
