# Controlled direct-audio importing

`ImportService` stores jobs in SQLite and processes one download at a time. Enqueue and retry use single SQL mutations to enforce a global queue bound and a per-owner bound. Job lists contain only their owner's jobs, with at most 100 results. A direct file's advertised MIME type is checked before download; actual content and metadata are validated by `vela-media` before the private track becomes available.

The network policy allows only HTTP/HTTPS on ports 80/443 without URL userinfo. It disables proxies, cookies, HTTP compression, and automatic redirects. Each manually followed redirect is checked again; each DNS result is checked in full and pinned to that request. HTTPS redirects cannot downgrade to HTTP. Native global-unicast IPv6 is supported conservatively; private, mapped, transition, documentation, multicast and other special-purpose addresses are rejected. Azure's host-service virtual address is rejected separately. There is no production switch that permits arbitrary private destinations.

Downloads stream into UUID-named temporary files and enforce the configured byte limit even without `Content-Length`. Requests have connect, stalled-read and total-transfer deadlines. Progress persists at most twice per second. A worker attempts transient connection/429/5xx failures at most three times, with bounded backoff. File validation failures, access denial, URL policy failures and storage errors require an explicit user retry. Failed-job messages exclude paths, request URLs, credentials and remote response bodies.

`ImportLimits` defaults to 64 active jobs globally, 8 per owner, a 100 GiB managed media budget, a 64 MiB free-space reserve, and a 15-minute transfer deadline. The server overrides the media budget from its configuration. Disk checks account for both download staging and the immutable publication copy. Filesystem free-space checks cannot reserve physical disk space against unrelated processes. The shared media service serializes its final managed-media quota check against uploads.

Cancellation is supported while queued or downloading. Once a job enters processing, validation and publication are allowed to finish and cannot be cancelled. Graceful shutdown interrupts downloads, removes partial files, and requeues those jobs. Processing finishes during graceful shutdown. Startup removes only owned staging file names and requeues interrupted jobs. Recovery restarts downloads from zero; a repeat download is deduplicated by exact BLAKE3 content hashing in media ingestion. Unrecoverable staging cleanup or database failure stops the worker so the server can surface the infrastructure failure.

The current source adapter is a direct downloadable audio URL. `ImportSource` is a compile-time extension contract that resolves downloadable assets using `ControlledHttp`. Uploads are handled separately by the server. ZIP, WebDAV, S3, Internet Archive item resolution, repository license discovery, RSS/podcast feeds and external playlist metadata adapters are not implemented. HTTP Range resumption and pausing are not implemented. An exact duplicate may be rejected by the conservative pre-download quota check when managed storage is full. Only one server process may operate on a data directory. This importer does not extract audio from streaming-service pages or bypass access restrictions.

Tests use real loopback HTTP fixtures, a real SQLite schema, and real generated PCM audio. Fixture routing exists only under `cfg(test)` and cannot be enabled in production. Coverage includes direct and redirected media download, exact deduplication, ownership, SSRF URL/address rejection, private redirects, redirect loops, restart recovery, cancellation after received bytes, shutdown cleanup, retries, unknown-length size limits, invalid audio, managed storage limits and concurrent queue quota enforcement.
